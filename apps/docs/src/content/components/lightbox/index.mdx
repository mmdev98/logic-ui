## Usage guidelines

- **The images fly:** the image grows out of its trigger when the viewer opens and flies back when it closes. Hide the trigger while it has `data-popup-open`.
- **One gesture engine:** swipe, pinch, double tap, pan and drag to close are handled together, so they never fight over a touch. The viewer needs no carousel or zoom library.
- **Your layout, your items:** the lightbox renders no thumbnails of its own. Lay out your page however you like and place a `Lightbox.Trigger` per item. Items can have any shape; the lightbox only needs a stable value for each.
- **No dependencies:** the lightbox needs no carousel, zoom, animation or image library, and no framework. `Lightbox.Media` wraps your own `<img>`, `<video>` or `<iframe>`; give it any `src` or `srcSet`.

Import the component and assemble its parts:

```jsx title="Anatomy"

  <Lightbox.Trigger />

```

## Examples

### Items

`Lightbox.Root` takes the items in `items`, with any shape. Each item needs a value that identifies it and stays the same when items are added, removed or reordered: by default its `id`, or whatever `itemToValue` returns. The parts take what they need as props: your `<img>` gets its `src` and `alt`, and `Lightbox.Media` gets the natural `width` and `height`, which give it the right shape before the image has loaded.

```tsx title="Items"
const photos = [
  { id: "1", src: "/photos/1.jpg", width: 1600, height: 1067, alt: "Valley" },
  { id: "2", src: "/photos/2.jpg", alt: "Portrait" },
];

<Lightbox.Root items={photos}>
  …
  <Lightbox.Viewport>
    {(photo) => (
      <Lightbox.Slide>
        <Lightbox.Media width={photo.width} height={photo.height}>
          <img src={photo.src} alt={photo.alt} />
        </Lightbox.Media>
      </Lightbox.Slide>
    )}
  </Lightbox.Viewport>
</Lightbox.Root>;

// Items without an `id`:
<Lightbox.Root items={files} itemToValue={(file) => file.path}>
  …
</Lightbox.Root>;
```

### Loading

The trigger loads the image before the viewer opens, so the image shows at once and flies at the right size. It has `data-pending` meanwhile. By default the item's `src` is loaded; pass `loadMedia` to choose how.

Inside the viewer, `Lightbox.Media` and its `Lightbox.Slide` have `data-loading` while the media loads and `data-error` if it fails. The state comes from the media's own events: `load` and `error` for an image, `loadeddata` for a video. Put a spinner or a message next to the media, inside `Lightbox.Media`, and show it with these attributes: everything in `Lightbox.Media` flies and follows the drag to close with it.

```tsx title="Loading and errors"
<Lightbox.Media width={photo.width} height={photo.height} className="group">
  <img src={photo.src} alt={photo.alt} className="group-data-error:invisible" />
  <span className="hidden group-data-loading:block">{/* spinner */}</span>
  <p className="hidden group-data-error:block">
    This image couldn’t be loaded.
  </p>
</Lightbox.Media>
```

`Lightbox.Media` only reads its direct `<img>`, `<video>` or `<iframe>` child (or the `<img>` of a `<picture>`), so an icon inside the message doesn't count. Content without one counts as loaded at once.

#### Resized images

Show smaller images as thumbnails and larger ones in the viewer by giving the `<img>` in `Lightbox.Media` its own `src` or `srcSet`. Pass `loadMedia` to `Lightbox.Root` so the viewer preloads the same URL before it opens.

```tsx title="Resized images"
import { Lightbox, loadLightboxMedia } from "@logic-ui/react/lightbox";

// Any image service that resizes from the URL.
const getViewerSrc = (photo: Photo) => `${photo.src}?width=2000`;

<Lightbox.Root
  items={photos}
  loadMedia={(photo) => loadLightboxMedia({ src: getViewerSrc(photo) })}
>
  {photos.map((photo) => (
    <Lightbox.Trigger key={photo.id} value={photo.id}>
      <img src={`${photo.src}?width=200`} alt="" />
    </Lightbox.Trigger>
  ))}
  <Lightbox.Portal>
    <Lightbox.Popup>
      <Lightbox.Viewport>
        {(photo: Photo) => (
          <Lightbox.Slide>
            <Lightbox.Media>
              <img
                src={getViewerSrc(photo)}
                srcSet={`${photo.src}?width=1000 1000w, ${getViewerSrc(photo)} 2000w`}
                sizes="100vw"
                alt={photo.alt}
              />
            </Lightbox.Media>
          </Lightbox.Slide>
        )}
      </Lightbox.Viewport>
    </Lightbox.Popup>
  </Lightbox.Portal>
</Lightbox.Root>;
```

### Video and other media

`Lightbox.Media` takes any media as its direct child: an `<img>`, a `<video>`, an `<iframe>`. It fits the media's shape inside the slide, flies it from the trigger and back, and follows the drag to close. Only images zoom: on other media the zoom gestures do nothing and `Lightbox.ZoomIn` is disabled. Give a video its natural `width` and `height`, or `Lightbox.Media` reads them once its metadata loads; give an embed its `width` and `height` (`16` and `9`). Pass your own `loadMedia` so a video item doesn't preload as an image.

```tsx title="Video"
<Lightbox.Viewport>
  {(item) => (
    <Lightbox.Slide>
      <Lightbox.Media width={item.width} height={item.height}>
        {item.type === "video" ? (
          <video src={item.src} controls playsInline preload="metadata" />
        ) : (
          <img src={item.src} alt={item.alt} />
        )}
      </Lightbox.Media>
    </Lightbox.Slide>
  )}
</Lightbox.Viewport>
```

A video pauses when its slide is no longer shown and when the viewer closes. While a player with `controls` has focus, the arrow keys stay its own, to seek and change the volume. An iframe keeps every touch to itself, so swipe beside it or use `Lightbox.Previous` and `Lightbox.Next`.

### Errors

When the media fails to load, `Lightbox.Media` and its `Lightbox.Slide` get `data-error`. Show a message inside `Lightbox.Media` with it, and hide the broken image: the box keeps its shape, so the message takes the image's place, flies in and out like it, and follows the drag to close. The viewer keeps working: swipe or use the arrows to move on, or close it. A failed image no longer zooms.

```tsx title="Errors"
<Lightbox.Media className="group">
  <img src={photo.src} alt={photo.alt} className="group-data-error:invisible" />
  <p className="hidden group-data-error:block">
    This image couldn’t be loaded.
  </p>
</Lightbox.Media>
```

### Thumbnails

`Lightbox.ThumbnailList` renders a `Lightbox.Thumbnail` per item inside the viewer, through a function child like `Lightbox.Viewport`. What's inside a thumbnail is yours: an image, a dot, a title. The list is a tab list and each thumbnail a tab, as in the WAI-ARIA tabbed carousel: the slides become their tab panels, and the thumbnail of the item shown has `aria-selected` and `data-active`.

- **Keyboard.** The strip is a single tab stop. The arrow keys move between thumbnails and show their item, and Home and End go to the first and last. With `activateOnFocus={false}`, the arrows only move focus and Enter shows the item.
- **Orientation.** `orientation` sets which arrow keys move and which way the strip scrolls: ← → for `"horizontal"` (the default), ↑ ↓ for `"vertical"`. The strip has `data-orientation`, so the same classes can style both.
- **Scrolling.** Give the strip `overflow: auto`. The active thumbnail glides to its centre, and is centred again when a CSS transition changes its size. The mouse can drag the strip (`data-dragging` meanwhile, and the drag doesn't click a thumbnail), and the wheel scrolls a horizontal strip. Touch scrolls natively.
- **Edges.** The strip has `data-overflow-start` and `data-overflow-end` while thumbnails are hidden past an edge: fade that edge with a mask, `data-overflow-end:mask-r-from-85%`.
- **Scrollbar.** The lightbox sets no styles, so hide the browser's scrollbar in CSS. The strip still scrolls: `[scrollbar-width:none] [&::-webkit-scrollbar]:hidden`.

```tsx title="Thumbnails"
<Lightbox.ThumbnailList orientation="vertical">
  {(photo) => (
    <Lightbox.Thumbnail aria-label={photo.alt}>
      <img src={photo.thumb} alt="" />
    </Lightbox.Thumbnail>
  )}
</Lightbox.ThumbnailList>
```

### Mobile gestures

The viewer works like the photo app of a phone:

- **Swipe** between images; the image follows the finger, carries on with the flick, and rubber-bands at the first and last image.
- **Pinch** to zoom around the fingers, and **double tap** to zoom in at the tapped point or back out.
- **Pan** a zoomed image; past its edge, the drag carries on to the next image.
- **Drag down** (or up) to close: the image follows the finger, the backdrop fades, and it flies back on release.
- **Tap** to hide or show the controls.

With a mouse or trackpad, drag swipes, double click zooms, and the wheel or a trackpad pinch zooms around the cursor.

#### Edge to edge

Like a phone's photo app: no padding around the image, translucent bars, and a tap hides them. Try it on a phone or with the browser's device toolbar.

### Styling

Every part is unstyled. Style the viewer with Tailwind (or any CSS), using the parts' data attributes and CSS variables:

- `Lightbox.Popup` has `data-zoomed` while the image is zoomed, `data-controls-hidden` after a tap hid the controls, and `data-starting-style` / `data-ending-style` while the image flies in and out. Fade the controls, not the popup: the image is inside it. From a control, read them with `in-data-*`: `in-data-controls-hidden:opacity-0`. Its `className`, `style` and `render` functions receive `zoomed`, `controlsHidden` and `activationDirection` with the dialog's state.
- `Lightbox.Popup`, `Lightbox.Viewport`, `Lightbox.Slide` and the parts that show the item have `data-activation-direction` (`left`, `right`, or `none` when the viewer opens): the side the item shown came from, mirrored in a right-to-left layout.
- `Lightbox.Popup` and `Lightbox.Backdrop` get `--lightbox-dismiss-progress` (0 to 1) while the image is dragged to close: `opacity-[calc(1_-_var(--lightbox-dismiss-progress,0))]`.
- `Lightbox.Popup` and `Lightbox.Backdrop` have `data-dragging` during a drag, and until the image settles back after a drag to close. Turn transitions off then (`data-dragging:transition-none`, or `in-data-dragging:transition-none` on a control), or whatever follows `--lightbox-dismiss-progress` lags behind the finger.
- `Lightbox.Viewport` has `data-dragging` during a gesture. Give it a size (`absolute inset-0`) and set the space between images with `gap-x-4`.
- `Lightbox.Slide`'s padding is the space around the media: `p-0` for edge to edge on phones, `md:px-24 md:py-18` on larger screens. Add `pt-[env(safe-area-inset-top)]` and the like for notches (with `viewport-fit=cover` on the page). It has `data-active`, and `data-loading` and `data-error` for its media.
- `Lightbox.Media` sets its own position and size, and the size of the media in it: style what's around the media, not its box.
- `Lightbox.Trigger` has `data-popup-open` while the viewer shows its item, from the opening flight to the end of the closing one. Hide it with `data-popup-open:invisible`: the thumbnail disappears from the page but keeps its place, as in a phone's photo app, and comes back when the image flies home. It also has `data-pending` while its image loads (`data-pending:opacity-60`) and `data-flying` while it flies.

```tsx title="Styling the viewer"
<Lightbox.Backdrop className="fixed inset-0 bg-black opacity-[calc(1_-_var(--lightbox-dismiss-progress,0))] transition-opacity duration-300 data-dragging:transition-none data-starting-style:opacity-0 data-ending-style:opacity-0" />
<Lightbox.Popup className="fixed inset-0 text-white outline-none">
  <Lightbox.Viewport className="absolute inset-0 gap-x-4 cursor-zoom-in in-data-zoomed:cursor-grab data-dragging:cursor-grabbing">
    {(photo) => (
      <Lightbox.Slide className="p-0 md:px-24 md:py-18">
        <Lightbox.Media>
          <img src={photo.src} alt={photo.alt} />
        </Lightbox.Media>
      </Lightbox.Slide>
    )}
  </Lightbox.Viewport>
  <Lightbox.Close className="absolute top-3 right-3 transition-opacity duration-200 in-data-dragging:transition-none in-data-controls-hidden:opacity-0 in-data-ending-style:opacity-0">
    ✕
  </Lightbox.Close>
</Lightbox.Popup>
```

### Keyboard

| Key        | Action                                       |
| :--------- | :------------------------------------------- |
| ← →        | Previous / next image, or pan while zoomed   |
| ↑ ↓        | Pan while zoomed                             |
| Home / End | First / last image                           |
| + −        | Zoom in / out                                |
| 0          | Reset the zoom                               |
| Esc        | Close; the image flies back to its thumbnail |

Inside a widget that uses the arrow keys itself, they stay that widget's: a Base UI `Toolbar`, `Lightbox.ThumbnailList`, a slider, a text field.

The package follows semver. Until `1.0.0`, a minor version (`0.x.0`) may break the API; each
breaking change is listed under its release.

## Unreleased

### Breaking changes

- **`Gallery` is now [Lightbox](/docs/components/lightbox)**, at `@logic-ui/react/lightbox`.
  Every part, type, hook and constant is renamed (`GalleryRoot` → `LightboxRoot`,
  `GALLERY_ZOOM_SCALE` → `LIGHTBOX_ZOOM_SCALE`), and the CSS variable
  `--gallery-dismiss-progress` is now `--lightbox-dismiss-progress`. The lightbox is the
  full-screen viewer only: the page around the triggers is yours.
- **Items are picked by value, not by index.** `Root` takes `value` / `defaultValue` /
  `onValueChange` (the open item's value, `null` while closed) instead of `open` /
  `defaultOpen` / `onOpenChange` and `index` / `defaultIndex` / `onIndexChange`. An item's
  value is its `id`, or what the new `itemToValue` returns. `Trigger` takes `value` instead of
  `index`. The open item stays open when items are added, removed or reordered.
- **`Item` is now `Slide`**, and takes no `index`: return it from the function passed to
  `Viewport`. With thumbnails, the slides are their tab panels.
- **`Image` is replaced by `Media`**, which wraps your own `<img>`, `<video>` or `<iframe>`:
  `<Lightbox.Media width={photo.width} height={photo.height}><img src={photo.src} alt={photo.alt} /></Lightbox.Media>`.
  It takes the natural `width` and `height`; the `src` and `alt` go on your element. The
  whole box flies and follows the pull to dismiss, and only an `<img>` zooms. `loadImage` is
  now `loadMedia` (and `loadLightboxImage` is `loadLightboxMedia`), and `LightboxImageStatus`
  is `LightboxMediaStatus`.
- **Items can have any shape.** `GalleryItemData` is removed. The parts take what they need
  as props, and `Description` takes a function child to show the item's caption:
  `{(photo) => photo.caption}`. `loadMedia` receives your item.
- **`Value` is now `Counter`.**
- **`ZoomValue`'s function child receives its state**, `{(state) => state.scale}`, instead of
  the scale.
- **Removed `List` and `More`.** Lay out the triggers with your own elements.
- **Removed `Toolbar` and `Separator`.** Use Base UI's [Toolbar](/docs/components/toolbar)
  and render each action as a `Toolbar.Button`: `<Lightbox.Next render={<Toolbar.Button />} />`.
- **Removed `Delete` and `Download`.** Build them as buttons in the popup.
- **`Image`'s `data-loaded` is replaced** by `data-loading` and `data-error`, on `Media` and
  its `Slide`.
- **`data-dragging` is now `data-swiping`**, on `Popup`, `Backdrop`, `Viewport` and
  `ThumbnailList`, like Base UI's drawer. `ThumbnailList`'s state field is `swiping`.
- **`data-popup-open` marks the trigger the image will fly back to**: the one of the item shown,
  or the one `closeTarget` picks. Before, it marked every trigger of the item shown.
- **`onValueChange` receives `eventDetails`** as its second argument, like Base UI's callbacks.
- **`Viewport` and `Slide` no longer clip.** Add `overflow-hidden` to the viewport in a viewer
  smaller than the screen.
- **Closed sets are string unions, not enums, named after their part like Base UI's.** Write the
  strings (`"loading"`, `"open"`, `"left"`) instead of `LightboxMediaStatus.Loading` and the
  like. `LightboxPhase` is now `LightboxRootPhase`, and `LightboxActivationDirection` is
  `LightboxRootActivationDirection`. `ThumbnailList`'s `orientation` is typed
  `LightboxThumbnailListOrientation`.

### New features

- `Lightbox.createHandle()` links triggers placed outside `Root` to it, like Base UI's detached
  triggers, and opens or closes the lightbox from code.
- **Any media.** `Media` shows a video or an embed as well as an image, and reads its loading
  state from the media's own events. A video pauses when its slide is no longer shown.
- `ThumbnailList` and `Thumbnail`: a strip of thumbnails inside the viewer, a tab list that is
  a single tab stop, with `aria-selected` on the item shown. `ThumbnailIndicator` is one
  element that glides to the active thumbnail, with its box as CSS variables.
- `Caption`: a slide's own text, which moves with it and describes it for screen readers.
- **Animation attributes.** `Popup`, `Viewport`, `Slide`, `Title`, `Description`, `Counter`,
  `Caption` and `ThumbnailIndicator` have `data-activation-direction` (`left`, `right` or
  `none`), the side the item shown came from. `Title` and `Description` with a function
  child, `Counter` and `Caption` have `data-starting-style` for a frame when the item
  changes, to animate the new text in. `Title` takes a function child, like `Description`.
- `Popup`'s `className`, `style` and `render` functions receive `zoomed`, `controlsHidden` and
  `activationDirection`. `Viewport` is a labelled carousel region.
- The arrow keys stay with a widget inside the popup that uses them itself, such as a Base UI
  toolbar, a text field or a video player, instead of also changing the image.
- **Where the image lands.** `closeTarget` on `Root` picks the trigger the image flies back to
  and focus returns to: `"active"` (the item shown, the default), `"opener"` (the trigger that
  opened the viewer) or `"nearest"` (the nearest item with a trigger, for a "+5" tile).
  `scrollToTrigger` (on by default) scrolls the page behind the viewer to keep that trigger in
  view.
- **Crossfade.** When the image flies to or from a trigger that shows something else (another
  item, or a trigger with the new `crossfade` prop, such as an avatar or a tile with a count), a
  copy of the trigger flies along and fades, so the image grows out of its look and turns back
  into it on the way home. `Trigger` has `data-crossfade`.
- **Change reasons.** `eventDetails.reason` tells what changed the item
  (`"swipe"`, `"trigger-press"`, `"escape-key"` …), and `eventDetails.cancel()` keeps the
  current item: a cancelled swipe or pull to dismiss springs back. `onOpenChangeComplete` is
  called once the image has landed.
- **A smoother flight.** It is computed on screen, so the shape and corners change evenly;
  a flight cut short starts the next from where the image is; after a pull to dismiss, the
  flight back starts at the speed of the finger. `--lightbox-flight-duration` and
  `--lightbox-flight-easing` on `Popup` and `Backdrop` let transitions go with it.
- **Gesture variables.** `Popup` gets `--lightbox-swipe-movement-x`, `--lightbox-swipe-progress`
  and `--lightbox-swipe-strength` during a swipe, `--lightbox-zoom-scale` and
  `--lightbox-zoom-progress`, and, with `Backdrop`, `--lightbox-dismiss-movement-x` and `-y`.
- **Custom transitions.** Each `Slide` has `--lightbox-slide-progress`, its distance from the
  centre in slides, and is placed with `translate`, leaving `transform` free for a cube, a fade
  or a coverflow. `Viewport`'s `neighbors` renders more items on each side (1 by default).
- Changing `value` while the viewer is open slides to the new item, as Next does.
- `Popup` takes focus when it opens, so its keys work at once; pass `initialFocus` to focus
  another element.

## v0.1.0

October 8, 2026. The first release.

### New components

- **[Gallery](/docs/components/lightbox)** (now Lightbox): thumbnails that open a full-screen image viewer.
  The image flies out of its thumbnail and back, and the viewer handles swipe, pinch to zoom,
  double tap, pan, pull to dismiss and the keyboard. Comes with toolbar parts for navigation,
  zoom, download and delete.
- **[Clipboard](/docs/components/clipboard)**: a button that copies a value and shows that it
  was copied. `Root`, `Trigger` and `Indicator` expose `data-copied`.

### Core components

- Dialogs, menus, popovers, selects, tabs and the other core components, each under its own
  path, such as `@logic-ui/react/dialog`.
- `@logic-ui/react/utils` exports the hooks the primitives are built on, such as
  `useControlled`, `useStableCallback` and `useTimeout`.

### Requirements

- React 19.
- Built on `@base-ui/react` 1.8.0.
